# stockstrategy 项目交接说明

更新时间：2026-10-08（Asia/Shanghai）

## 项目边界

本文只记录 `stockstrategy` 项目：Go 行情与策略服务、Web 页面、Python 行情脚本及其定时任务。`inStock` 是另一套独立项目，容器、数据目录、任务和运行状态均不属于本文范围。

## 部署位置与数据

- 服务器项目目录：`/root/johnson/stock-strategy/`。
- 持久化根目录：`/mnt/4TB/dockerf/stockstrategy/`；部署前会检查 `/mnt/4TB` 是否为挂载点。
- Go 与 Python 共用行情数据库：`/mnt/4TB/dockerf/stockstrategy/data/easy-stock/stock-data.db`。API 容器通过 `A_STOCK_DATA_DB` 使用容器内 `/data/easy-stock/stock-data.db`；盘后脚本通过 `EASY_STOCK_DATA_DB` 指向同一宿主机文件。
- 策略任务日志位于 `/mnt/4TB/dockerf/stockstrategy/logs/service/`；锁文件位于 `/mnt/4TB/dockerf/stockstrategy/data/service/locks/`。
- SQLite 日线唯一键为 `(market, code, date)`，用于避免重复记录。

## 本机构建与发布

发布脚本位于 `stock-strategy/build-and-deploy.ps1`，在 `stock-strategy/` 目录运行：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\build-and-deploy.ps1 -Server <Docker主机地址>
```

脚本先核对 SSH 主机身份、当前容器健康状态和服务器资源；最低门槛为可用内存 512 MiB、数据盘剩余空间 1 GiB、Docker 盘剩余空间 1 GiB。随后在本机编译 Go 后端和 Web 前端，将构建产物及源码打包上传；服务器仅执行受资源限制的镜像封装、隔离健康检查和容器切换，不在服务器编译 Go 或 Node.js。

API 与 Web 的新版本未通过健康检查时会回滚旧容器。发布保留外部持久化数据和日志。本机临时构建目录及进程环境变量由脚本清理或恢复，`.build-cache/` 会保留以加快后续构建。SSH 使用非交互密钥认证；不得把密码、令牌或完整环境变量写入仓库或日志。

该脚本将 `source/` 同步到服务器项目目录。盘后 Python 任务也从这份源码运行，因此 `easy-stock-service/*.py` 的变更会随发布同步到定时任务实际使用的路径。定时规则单独维护在 `docker/stockstrategy-market-append.cron`，安装脚本为 `docker/install.sh`；普通 Go/Web 发布不会重写该 cron 配置。

## 盘中信号与日线持久化

- Go 后台的自适应任务按资源与上游状态选择 15、30、45 或 60 分钟间隔，只更新盘中信号和概览，不持久化个股日线。
- 日线请求绕过原始 HTTP 响应缓存；K 线接口只返回已完成日线，不从请求处理器写入行情数据库。
- A 股日线由 `docker/market-append.sh cn` 在每个工作日 15:40（`CRON_TZ=Asia/Shanghai`）回补。包装脚本持有文件锁、设置共享数据库和交易日历路径，并把输出写入 `logs/service/market-append-cn.log`。
- `bars.py` 在 15:40 前拒绝当日落库；历史回补写入时拒绝晚于最近已完成交易日的数据。每条记录还需通过日期与 OHLC 有效性校验；缺失或异常数据会留待后续任务重试。
- 美股和币圈分别由同一包装脚本以 `us`、`crypto` 参数运行，时间规则见 `docker/stockstrategy-market-append.cron`。
