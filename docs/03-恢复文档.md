## 1. VM 更换时会发生什么(已复查,2026-10-02)

| 类别 | 是否丢失 | 说明 |
|---|---|---|
| home 目录下全部文件 | 不丢失 | 代码/数据/账本/日志/strategy.yaml/配置/memory/goals,随 home 持久化 |
| 定时任务(cron) | 不丢失 | 由 runtime 托管,更换后自动恢复执行 |
| 运行中的进程 | 丢失 | 后端 :20081、前端 :20073 会死,需拉起 |
| home 之外的文件 | 丢失 | /usr/local/bin、/etc、/var、系统级 pip 包(本系统未在之外写过任何东西) |
| Python 第三方依赖 | 不丢失 | 已 vendor 到 `~/.local`(随 home 持久),不再依赖系统 dist-packages |

**结论:数据不丢,进程会死。** 数据底座(bars.db)和自动回补机制(bars.py)都在 home 里,更换后原地可用,无需"还原"。

## 2. 自动恢复链条

1. VM 更换完成,home 目录恢复,定时任务由 runtime 自动恢复调度。
2. `easy-stock-healthcheck`(每15分钟)首次运行:curl 后端失败 → 执行 `start.sh` 拉起 → 复检。
3. `easy-stock-web-healthcheck`(每15分钟):同样拉起前端(含后端依赖检查)。
4. 最长恢复时间:约 15 分钟(巡检间隔)。2026-10-01 03:14 已真实验证过拉起。

注意:更换后到巡检拉起之间的窗口内,依赖后端的任务(如数据回补)会失败;回补机制为 fail-closed,
会如实报告缺口、不写脏数据,下一轮自动补上。

## 3. 手动恢复(一键)

```bash
bash ~/workspace/easy-stock-service/recover.sh
```

脚本做三件事,全部 10 项通过即恢复完成:

1. 检查:后端 :20081、前端 :20073、Python 依赖、strategy.yaml 可解析
2. 检查:bars.db、三套账本、.env、push_config.json 存在
3. 自愈:缺失的进程自动执行 start.sh 拉起并复检

## 4. 从备份恢复(灾难场景:home 被清空)

### 4.1 备份内容

- 本机快照: `~/workspace/backups/easy-stock-full-20261002.tar.gz`(43M,代码+账本+规则全量)
- Google Drive: `easy-stock-release-YYYYMMDD.tar.gz`(发布包,见第5节) + 三份文档

### 4.2 恢复步骤

**一键恢复(推荐):** 准备三个文件放同一目录 —
`easy-stock-release-*.tar.gz`(发布包)、`easy-stock-keys-*.tar.gz`(密钥包)、`restore.sh` —
然后执行:

```bash
bash restore.sh
```

脚本自动完成:解包 → 灌入密钥(600权限) → npm ci 重建前端依赖 → 补 Python 依赖 →
拉起后端/前端 → 跑 recover.sh 验收(10/10 通过即成功)。已在沙盒实测全链路通过。

**手动恢复(备用):**

```bash
# 1. 取回发布包(从 Google Drive 下载到本机)
# 2. 解压到 workspace
cd ~/workspace && tar -xzf easy-stock-release-20261002.tar.gz
# 3. 重建前端依赖(发布包不含 node_modules)
cd ~/workspace/easy-stock-web && npm ci
# 4. 恢复 Python 依赖(如 ~/.local 被清空)
pip install --target=$HOME/.local/lib/python3.12/site-packages --break-system-packages \
  "numpy==1.26.4" requests pyyaml pandas lxml matplotlib
# 5. 填入两个密钥文件(备份中不含 Key,需手动重建,权限 600)
#    easy-stock-service/.env (A_STOCK_TOKEN)
#    easy-stock-service/push_config.json (企业微信机器人 Key)
# 6. 启动并验证
bash ~/workspace/easy-stock-service/start.sh
bash ~/workspace/easy-stock-web/start.sh
bash ~/workspace/easy-stock-service/recover.sh
```

### 4.3 备份中不含什么(需手动重建)

- `.env` 中的 A_STOCK_TOKEN、`push_config.json` 中的机器人 Key(安全起见永不进备份)
- 定时任务定义(runtime 侧,如丢失需按 02-部署文档第6节重建)
- memory/ 与 goals/(AI 侧,如丢失不影响交易执行,只影响 AI 的上下文记忆)

## 6. 故障排查

| 现象 | 检查 | 处理 |
|---|---|---|
| 后端 /api/health 不通 | `tail -30 logs/stdout.log` | bash start.sh;仍失败则看日志报用户 |
| 前端白屏/连不上 | 后端是否健康 | web 的 start.sh 会先拉后端 |
| 脚本报 ModuleNotFoundError | `python3 -c "import numpy"` | 重装 vendor 依赖(4.2第4步) |
| 定时任务没跑 | cron 工具查看任务状态 | runtime 托管,一般自动恢复;长时间无恢复则报用户 |
| 推送没收到 | push_config.json 是否存在/企业微信机器人是否有效 | 只走企业微信通道;检查 Key |
| 数据缺口 | ensure_bars 返回缺口 | fail-closed 正常行为;检查上游节流(upstream_throttle.json)与后端健康 |
