# SBC 与桌面关注及证据联动闭环实施

## 范围与版本边界

本记录只覆盖 stock-strategy Go/Web 独立仓库，实施于用户授权的当前 `main`。Python/TK/ATS 代码位于上层 pyQuant3 仓库的 `stock_standalone` 子目录，该子目录当前没有独立 `.git`；其实现与验证记录在对应任务文档。本次没有跨仓库复制源码或合并 Git 历史。

实施范围为审核方案 S1–S4：SBC 一键关注、共享只读上下文、证据事件和来源化关注状态。策略采纳（审核方案 S5）不在本次范围内，不改变交易准入、风控或执行行为。

## 已实施

- Go API 与 SQLite linkage 服务：桌面目标、关注命令及操作查询、上下文/事件/证据接口、授权与目标边界校验、请求幂等和操作账本。
- 桌面 POST 的 ACK 丢失后，过期 `pending` 投递先按原 operation ID 查询桌面收件账本；真实回执可恢复，桌面不可达时保留查询重试，不再误报过期或盲目重发。
- 关注状态使用 workspace 级 revision、来源和 tombstone 表达；旧状态可迁移；意图 ID 正文冲突可识别，快照在同一读事务内读取。
- 上下文聚合题材身份、热度、连板天梯和有日期/来源/新鲜度/覆盖信息的 ATS、TK、Instock 证据。ATS 龙头角色只对同交易日新鲜证据生成新增/变化事件；不以不完整候选样本缺席推断角色退出。
- Web SBC 提供目标选择、一键添加、操作状态轮询、断线重试恢复及共享证据展示，增加 Instock 候选命中、历史或未覆盖说明；来源面板可查看工作区关注来源，按来源撤销，或经显式确认全局清除并写入 tombstone。
- Go 证据来源白名单登记 `instock.candidates`；原 SBC 分析和策略决策代码不由该功能改写。

## 运行配置契约

- Go 使用已有 `A_STOCK_TOKEN` 鉴权；联动数据库与桌面目标文件可用 `A_STOCK_LINKAGE_DB`、`A_STOCK_LINKAGE_TARGETS` 指定，未指定时落在现有持久化数据目录。
- 目标文件每个桌面节点包含 `node_id`、`workspace_id`、`base_url`、`key_file`、`enabled`。`base_url` 必须是带端口的私有 IPv4 地址；密钥至少 32 字节，`key_file` 可相对目标文件定位，密钥不入 Git。
- 桌面 `global.ini` 新增项默认关闭：现场启用 `linkage_enabled`，配置 `stock_strategy_base_url`、`stock_strategy_token_file`、`ipc_node_id`、`ipc_workspace_id`、`ipc_peer_allowlist`、`ipc_key_file`；新 JSON 网关默认 `ipc_bind_host=auto_lan`、端口 `26676`、公布地址 `auto`。
- Go 目标配置的 node/workspace 与桌面配置一致，目标 `base_url` 指向桌面网关；桌面 allowlist 只放行 Go 服务私网地址。当前未填写生产地址、token 或密钥，也未部署到 LAN。
