# TDX 原生 Go 接入与确认限制审核

日期：2026-10-10

## 结论

实现 Go 原生 TDX K 线/股本读取、外置结构化缓存、3/5 日分时，以及具备覆盖门槛的分钟滞后关系评分。两项原限制改为按实际数据动态说明；历史换手率仍为估算，分钟关系仍是当前样本的相关性，不能直接全部删去风险提示。

## 变更

- `internal/providers/tdx`：握手、压缩解包、分页、日期/价格/量额解析、股本、取消/超时/节点降级、外置 SQLite。
- `internal/httpapi/tdx.go`：鉴权下原生多日接口和原行情源兼容接入；分钟昨收来自日线。
- `intraday_vwap.go`：真实 TDX 成交额累计、连续多日窗口与逐日模式分离。
- 前端 `KLineExplorer`：3 日/5 日分时按钮，沿用缩放、最新端锚定及弹窗。
- `minute-influence` / `use-theme-minutes`：最多 16 只当前页证券、同节点对照、按时间对齐、覆盖/日期门槛和 60 秒轮询。
- `short-term`：按数据覆盖启用分钟评分；金额/换手率需近 5 日 80% 有效覆盖，估算换手率继续扣减置信度。

## 缓存与环境

新增数据仅写 `MarketDataDBPath` 同目录的 `tdx-cache.db`。生产路径 `/data/easy-stock/tdx-cache.db` 对应外置盘 `/mnt/4TB/dockerf/stockstrategy/data/easy-stock/tdx-cache.db`。不增加 Docker 的 Python/Go 编译环境，不增加库依赖，不改变共享日线数据库及交易执行。

## 验证和发布

Go 协议、缓存、异常边界、HTTP、SBC 回归通过；相关前端 14 项回归及完整 165 项前端回归通过。部署主机 Go 独立只读验证分钟/5 分钟/日线各 1280 根及单位一致性通过。随后使用部署手册第 9 节的锁、健康检查、回滚流程发布；最终发布号及线上观察在项目交接文档中补记。

## 后续

盘中时段观察节点延迟/覆盖。精确历史换手率需历史股本；完整板块因果带动力不能由当前页滞后相关性确认。北交所、指数专用协议、盘口、逐笔和交易 API 不在本次实现范围。

### 五日图交互补充修复

线上首次验证五日 1200 根数据时，浏览器自动化出现交互超时；三日及重新打开的五日视图随后能够正常展示。审核发现每根 SVG 标题重复创建 `Intl.DateTimeFormat`，现改为复用三种格式化器，补充 1200 根完整渲染和无逐根 `toLocaleString` 调用回归。页脚同步标明 TDX 优先及旧源降级。没有修改行情计算或交易行为。
