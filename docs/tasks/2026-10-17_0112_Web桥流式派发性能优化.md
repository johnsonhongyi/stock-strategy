# Web 桥流式派发性能优化

日期：2026-10-17，Asia/Hong_Kong。本文件归独立 `stock-strategy/source/` 版本库；桌面桥代码在外层主库管理。

## 已实现

- `desktop_delivery.go`：共享数据库句柄、单连接事务、进程内可合并通知、统一长轮询领取、SSE 对话/研究快照；订阅有数量上限，取消时回收订阅，慢客户端写入有期限。
- `codex_chat.go`：领取/会话/到期索引；返回剩余预算与排队耗时；终态幂等；模型不匹配、租约替换、取消、记录不存在等有明确错误码。
- `codex_stock_research.go`：下发调用 context 的实际 deadline；进程内通知唤醒，15 秒低频兜底替代 250ms 查库；取消后保留任务墓碑，避免立即删除造成迟到回执不可诊断。
- `auto_follow_ai.go`、`linkage/registration.go`、`server.go`：增加 HMAC 授权范围内的 `next`、`lease` 路由，临时数据库错误返回 503，旧接口仍可使用。
- `stockanalysis/research_service.go`：研究阶段/终态持久化成功后通知订阅者，快照使用原 `Public()` 契约。
- `desktop-chat.ts`、`task-events.ts`、`use-stock-research.ts`：携带既有认证读取 SSE；增量马上更新，旧服务或断线使用原 GET 回退；队列等待、用户中止、终态和解析缓冲均有界。
- 同步 `easy-stock-web` 与 `easy-stock-analysis/frontend` 的相关改动，保留两份前端原有版本差异，没有整体互相覆盖。
- 研究数据、证据时效、引用校验、研究等级、所选模型/effort、只读权限和交易门禁保持原契约。

## 故障处理与保留

- 取消/过期任务不会被迟到结果改回完成；旧 token 不能覆盖新租约。
- 数据库错误不会冒充普通 409；通用模型调用错误不再错误标注为 Hermes。
- 研究临时任务终态/取消记录至少保留到 expires_at 后 24 小时，统一领取时限频分批清理；普通用户对话 session 不按研究规则清理。
- 桌面侧持久 outbox 负责终态重发，重试原结果，不再次发起模型请求。

## 验证

- 14 项 Go HTTP/API 专项测试通过，覆盖签名领取、并发唯一所有权、取消墓碑、剩余时限、SSE 终态和跨用户隔离。
- `internal/stockanalysis` 与 `internal/linkage` 全量测试通过。
- 9 项 Web 对话/SSE 测试通过，TypeScript 与 Vite 生产构建通过；上游前端对应代码已同步，未为其单独安装依赖。
- Linux/amd64、CGO_ENABLED=0 API 交叉构建通过；未替换生产 API 二进制。
- 两库 diff 空白检查通过；未部署、未连接真实下单环境、未使用真实模型做基准。
- 30 次隔离“通知→领取响应”测量 P50=2.9923ms/P95=3.9895ms，只代表本机已认证等待请求和 SQLite 的派发段，不代表端到端研究耗时。

## 发布要求

- 需要与外层主库的常驻引擎、异步发送、outbox 及打包配置协同发布，建议 API → Web → 桌面桥。
- 按本库现有发布/健康/回滚流程执行；本轮没有替换生产产物或重启服务。
- 发布后核对实际版本、桥身份、SSE 代理是否及时 flush，并采集真实冷/热对话与研究分阶段延迟。
- 当前保留单桥串行执行；多 worker 或模型阶段合并只有在实测和质量评估后才启用。
