# 子仓库开发与分支规则

## 默认分支

- 本子仓库默认在本地 `main` 开发和提交。用户未指定分支时，直接使用当前 `main`；不使用已退役的 `oss-main`，也不为每项任务创建 `codex/*` 分支。
- 开始前检查仓库根目录、当前分支、远程和工作区状态。若当前不在 `main`，先核实分支用途和未提交内容，不擅自切换、重置或覆盖工作。
- 远程名称或 Git tracking 配置不改变默认分支。只有用户明确指定分支时才改用其他分支。

## 提交与推送

- 用户要求“提交”时，在本地 `main` 创建提交；提交不代表允许推送。
- 只有用户明确要求推送时才推送。推送前核实远程、目标分支、提交内容和工作区状态。
- 不混入与当前任务无关的已有改动；不覆盖用户未提交内容。

## 历史分支清理

- 清理前检查分支相对 `main` 的文件差异、独有提交、补丁是否已等价合入、远程跟踪状态及 `git worktree list`。
- 仅在分支没有独有功能改动、没有未保留提交、未被工作树使用且不承担远程协作时删除本地分支。
- 存在功能差异或工作树依赖的分支应保留；如有同一提交的重复分支名，只能在另一个引用仍完整保留该提交且无人使用后，删除冗余别名。
- 删除远程分支需要用户明确要求。
