# 子仓库开发与分支规则

## 默认分支

- 本子仓库默认在本地 `main` 开发和提交。用户未指定分支时，直接使用当前 `main`；不使用已退役的 `oss-main`，也不为每项任务创建 `codex/*` 分支。
- 开始前检查仓库根目录、当前分支、远程和工作区状态。若当前不在 `main`，先核实分支用途和未提交内容，不擅自切换、重置或覆盖工作。
- 远程名称或 Git tracking 配置不改变默认分支。只有用户明确指定分支时才改用其他分支。

## 提交与推送

- 用户要求“提交”时，在本地 `main` 创建提交；提交不代表允许推送。
- 只有用户明确要求推送时才推送。推送前核实远程、目标分支、提交内容和工作区状态。
- 不混入与当前任务无关的已有改动；不覆盖用户未提交内容。

## 历史分支清理

- 清理前检查分支相对 `main` 的文件与行为差异、独有提交、远程跟踪状态、历史文档和 `git worktree list`。
- 以功能为准判断是否对齐：提交祖先关系或补丁 ID 不同本身不代表功能缺失；若 `main` 已完整实现相同或更完整的行为，且分支特有文档/配置已保留或确认无需迁移，该分支可视为已对齐。
- 仅在确认没有主线未覆盖的功能或需保留资料、没有活动 worktree、没有远程协作依赖后，删除本地历史分支。
- 存在独有功能、未处理资料或工作树依赖的分支应保留；同一提交的重复分支名可在确认其他引用完整保留提交后删除冗余别名。
- 删除远程分支需要用户明确要求。
